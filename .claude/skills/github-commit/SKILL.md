# 🛠️ Skill Details

このスキルは、コミットメッセージのルールを定め、プロジェクトのコードベースに対する変更を明確かつ一貫性のある方法で記録することを目的としています。

## コミットメッセージのルール

- **言語**: コミットメッセージはすべて日本語で記述してください。
- **フォーマット**: Conventional Commits に厳密に従ってください。
- **簡潔さの優先**: 最初の1行（要約）は `<type>(<scope>): <description>` の形式とし、Issue番号やリンクは含めないでください。
- **記述内容**: 「何をしたか」を短く簡潔に記述してください。

## 変更差分確認コマンド

- Current git status: !`git status`
- Current git diff (staged and unstaged changes): !`git diff HEAD`
- Current branch: !`git branch --show-current`
- Recent commits: !`git log --oneline -10`

## コミットの手順
1. 現状の変更差分を確認してください。
2. 変更ファイルを適切な単位に分けてください
3. 分けた単位別にコミットメッセージのルールに従って、コミットメッセージを作成してください。
4. コミット前に、作成したコミットメッセージを提示して、内容の確認と必要に応じた修正を行ってください。
5. ユーザーの確認が取れたら、コミットを実行してください。

## コミット時の制約
- セキュリティやプライバシーおよび一般的なコミットルールなどの観点から、コミットするファイルとしてふさわしくないファイルが変更差分に存在する場合は、コミット前に<🚨重大な報告>としてユーザーに通知するとともに、絶対にコミットしないこと。
- Co-Authored-by は絶対に使用しないこと。

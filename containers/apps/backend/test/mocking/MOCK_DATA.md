添付ファイルの内訳:

- 画像添付: `picsum.photos`から取得した画像を`/file-storage/upload`経由で再アップロード
- PDF添付: スクリプト内で生成した簡易PDFバイナリを`/file-storage/upload`経由でアップロード(外部URLに依存しない)

## 投入方式

| 対象                                             | 方式                                                                           | 理由                                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| ユーザー作成・フレンド関係・画像/PDFアップロード | HTTP API経由(`/auth/sign-up`・`/friendships/requests`・`/file-storage/upload`) | パスワードハッシュ化・JWT発行等の認証ロジックを二重実装しないため              |
| Face作成・Seed作成                               | repository層を直接呼び出し(`repo.createFace()`・`repo.createSeed()`)           | `createdAt`をusecase層の`new Date()`上書きなしに、相対日付で自由に指定するため |

## 実行手順

開発コンテナ(`backend`サービス)内で以下を順に実行する。

```bash
# 1. DBを空の状態にする(既存データは全て削除される)
pnpm --filter backend db:reset

# 2. マイグレーションを再適用してテーブルを作り直す
pnpm --filter backend db:migrate

# 3. モックデータを投入する
pnpm --filter backend mock:add-seed
```

- `mock:add-seed`は内部で`cd test/mocking && tsx seed-mock-data.ts`を実行する(`package.json`の`scripts`参照)。
- 投入完了後、`mainuser@example.com` / `password1234`でサインインすると、動作確認のメインユーザーとしてすぐに各機能を確認できる。
- 既にDBにデータがある状態(初回セットアップ後や、他の手動テストの後)でいきなり`mock:add-seed`だけを実行すると、メールアドレスの重複でユーザー作成が失敗するため、必ず手順1・2を先に行うこと。

## 運用上の注意

- メールアドレスが決定論的(`{key}@example.com`)なため、再実行すると重複エラーになる。再実行する場合は先に `pnpm --filter backend db:reset` → `pnpm --filter backend db:migrate` でDBをクリアしてからスクリプトを実行すること。
- 本データは開発・レビュー環境の動作確認用であり、`frontend-bff/src/mocks/`(Storybook用データ)とは完全に独立している。互いに参照し合わない。

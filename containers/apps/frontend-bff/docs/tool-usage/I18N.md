# フロントエンド BFF 多言語対応（i18n）実装ドキュメント

## 概要

`containers/apps/frontend-bff` に対して、日本語（`ja`）・英語（`en`）・フランス語（`fr`）の多言語対応を実装した。  
対象ブランチ: `feat/frontend-bff-i18n`

## 使用ライブラリ

### [next-intl](https://next-intl-docs.vercel.app/) `^4.9.2`

**選定理由:**

| 観点                                  | 理由                                                                                                             |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| App Router 対応                       | Next.js App Router（Server Components / Client Components）の両方に対応した唯一の成熟した i18n ライブラリ        |
| `getTranslations` / `useTranslations` | サーバー側・クライアント側で API が統一されており、コンポーネントの性質（Server/Client）に合わせて使い分けられる |
| ルーティング統合                      | `createMiddleware` で `/[locale]/...` へのリダイレクト処理を自動化できる                                         |
| メッセージ型安全                      | JSON メッセージファイルから TypeScript 型を自動生成するため、キーの typo をコンパイル時に検出できる              |
| 軽量・依存少                          | `next-intl` 単体で完結し、追加の polyfill や設定が不要                                                           |

他候補として `i18next` + `react-i18next` も検討したが、App Router の Server Components との相性問題（コンテキスト未対応）や設定の複雑さから除外した。

## アーキテクチャの補足

### ロケール検出の仕組み

```
ブラウザリクエスト
      │
      ▼
middleware.ts  ← createMiddleware(routing)
      │  Accept-Language ヘッダーを解析
      │  NEXT_LOCALE Cookie が存在すればそちらを優先
      │
      ▼
/[locale]/... にリダイレクト（ja がデフォルト）
      │
      ▼
[locale]/layout.tsx
  └─ getMessages() でサーバー側メッセージ取得
  └─ NextIntlClientProvider で全子コンポーネントに配布
```

### Server / Client 使い分け

| 状況                               | 使用 API                                                                      |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| Server Component（async 関数）     | `getTranslations('namespace')` from `next-intl/server`                        |
| Client Component（`'use client'`） | `useTranslations('namespace')` from `next-intl`                               |
| 相対時間（クライアント側）         | `useRelativeTime()` フック（内部で `useTranslations('relativeTime')` を使用） |

### メッセージファイル構造

翻訳キーはコンポーネント単位でネームスペースを分割している。

```
src/i18n/messages/
├── ja.json  (25 ネームスペース)
├── en.json  (25 ネームスペース)
└── fr.json  (25 ネームスペース)
```

新しいロケールを追加する場合は、このディレクトリに `{locale}.json` を追加し、`routing.ts` の `locales` 配列に追記するだけで対応できる。

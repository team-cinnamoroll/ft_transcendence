# MultiFace 新構想 UI/UX仕様（スマホ比率）

## このドキュメントの目的

本ドキュメントは、MultiFace 新構想のスマホ比率 UI/UX を定義する。
片手で素早く書けることを最優先に、`Writing` / `Reflection` / `Collect` の 3 タブをどう配置するかを示す。
現在、UIデザインの正本およびワイヤーフレームはFigmaで管理されているため、本ドキュメントは機能設計や仕様定義に特化する。

共通方針は [docs/frontend-bff/NEW_CONCEPT_UI_UX.md](docs/frontend-bff/NEW_CONCEPT_UI_UX.md) を参照する。

---

## 1. スマホ比率の基本方針

- スマホ幅を基準に設計する
- 主導線は片手で届く下部に置く
- 1画面でやることは 1 つに絞る
- 入力や編集はフルスクリーンシート、またはボトムシートを優先する
- 一覧は縦スクロール前提で、比較よりも連続操作を優先する
- UIデザインの正本はFigmaとし、全体的なテーマは Slate-100 の背景に白のカード、Indigo のグラデーションを用いる。

---

## 2. ナビゲーション構成

- 画面下部に 3 タブを固定表示する
  - `Writing`
  - `Reflection`
  - `Collect`
- アプリ起動時は `Writing` タブを初期表示とする
- タブ切り替えは常時 1 タップで行える
- 投稿作成の主要 CTA は `Writing` タブ内下部に固定表示する
- 初回ユーザーでも最初に開くのは `Writing` タブとする

---

## 3. 画面詳細仕様

## 3-1. Writing タブ

### 目的

思いついた瞬間に止まらず書けること。

### レイアウト

1. **共通ナビゲーションバー（上部）**
   - 画面上部固定
   - タイトル `Multi Face`
2. **ページヘッダー**
   - タイトル `Writing` （本体側に表記）
3. **メイン入力エリア**
   - 画面全体を入力フォームとして利用する
   - 本文入力欄
   - フェイス選択（チップ形式）
   - `保存` / `種として保存` アクション
   - 公開範囲切り替え

### 表示優先順位

- 起動直後に最初に視認されるのは `メイン入力エリア` とする
- `Writing` タブでは補助情報を置かず、ファーストビュー内の主目的を「書き始める」「投稿する」に絞る

### Empty状態

- フェイス 0 件: `最初のフェイスを作る` を表示し、作成後に入力状態へ戻る

### 初回ユーザー導線

- フェイス 0 件の場合、通常の Empty 状態ではなく初回案内カードを表示する
- 案内カードには次を表示する
  - `最初に 1 つフェイスを作る`
  - `あとから増やせます`
  - `作成後はすぐ書き始められます`
- フェイス作成完了後は自動で `Writing` に戻り、入力できるようにする

### AC

- アプリ起動直後、最初に見える主要要素が入力欄である
- 投稿開始のために画面遷移を挟まない

## 3-2. Reflection タブ

### 目的

短時間で気づきを得て、必要ならフェイス構成も見直せること。
過去の投稿履歴の振り返りもここで行う。

### レイアウト

1. **共通ナビゲーションバー（上部）**
   - 画面上部固定
   - タイトル `Multi Face`
2. **ページヘッダー**
   - タイトル `Reflection` （本体側に表記）
   - 右上に `フェイス管理` への導線
3. **フェイス一覧群**
   - 自分が作成したフェイスの一覧として、縦長の長方形（中に正方形の画像、下部にタイトルと詳細）のカードを2列グリッドで表示
   - 各フェイスにはテーマに適した、大きく視認性の高い画像を合わせて表示する
   - カードタップで該当フェイスに絞り込まれた閲覧状態へ遷移
4. **最近の投稿履歴**
   - 新着順のタイムライン一覧表示
5. **再発見カード群等**
   - 昔保存した種などとの再会
   - この気づきから書く（行動 CTA）

### フェイス管理シート

- 右上の `フェイス管理` やフェイス一覧カードからフルスクリーンシートで開く
- 作成、編集、公開設定を扱う

### Empty状態

- `投稿がありません`（最初はフェイス一覧から新規フェイスを作成するなど）を表示

### AC

- 1 画面で要約、変化、再発見を縦スクロールで確認できる
- フェイス管理は `Reflection` タブから完結して開ける

## 3-3. Collect タブ

### 目的

外部刺激や種をため、あとで書く材料へ変えやすくすること。

### レイアウト

1. **共通ナビゲーションバー（上部）**
   - 画面上部固定
   - タイトル `Multi Face`
2. **ページヘッダー**
   - タイトル `Collect` （本体側に表記）
3. **上部セグメント切り替え**
   - `種`
   - `保存アイテム`
   - `発見`
4. **追加 CTA 行**
   - `URLを保存`
   - `テキストメモを保存`
5. **一覧**
   - 1 カラム
   - 新着順

### 発見画面

- `発見` セグメントで開く
- 一覧カードに表示する項目
  - タイトルまたは投稿冒頭
  - 出典種別（他人投稿 / 外部情報）
  - おすすめ理由
  - `保存してメモする` ボタン
- 並び順は人気順ではなく、次を優先する
  - 関連フェイスとの近さ
  - 最近保存した内容との近さ
  - 最近書いた内容との近さ
- 1画面目の先頭にランキングや件数競争の表現は置かない

### 保存入力シート

- ボトムシートまたはフルスクリーンシートで開く
- 必須入力
  - URL または本文
  - 気になった理由
  - 関連フェイス

### 投稿変換

- `投稿にする` を押すと `Writing` 用の投稿入力シートを開く
- 元の保存内容を引用表示して始める

### Empty状態

- 種 0 件: `とりあえず種として残してみる`
- 保存アイテム 0 件: `気になった URL やメモを保存する`

### AC

- 種と保存アイテムを上部切り替えで迷わず行き来できる
- `発見` から 1 ステップで保存導線へ進める
- 保存から投稿変換まで親指操作中心で完結できる

---

## 4. スマホ比率の表示密度ルール

- 1 画面目で主 CTA が必ず見える
- 1 画面目で入力欄が最も大きく見える
- 投稿カードは 1 画面目に 2〜3 件見える密度を目安にする
- 主要操作ボタンのタップ領域は 44px 以上を前提にする
- 長文は 3 行で折りたたみ、詳細は展開で見る

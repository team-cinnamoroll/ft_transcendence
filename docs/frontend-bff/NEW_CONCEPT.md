# MultiFaceの新構想

## このドキュメントの目的

本ドキュメントは、MultiFace を「多面性を整理し、自己理解を深めるための短文記録SNS」として再定義し、
そのまま実装 ISSUE に分解できる状態まで仕様を具体化することを目的とする。

対象は、コンセプト・機能方針・MVP の成立条件である。
実際の UI/UX 構成、画面仕様、導線、実装 ISSUE 分解は共通方針を [docs/frontend-bff/NEW_CONCEPT_UI_UX.md](docs/frontend-bff/NEW_CONCEPT_UI_UX.md)、
スマホ比率レイアウトを [docs/frontend-bff/NEW_CONCEPT_UI_UX_MOBILE.md](docs/frontend-bff/NEW_CONCEPT_UI_UX_MOBILE.md)、
PC比率レイアウトを [docs/frontend-bff/NEW_CONCEPT_UI_UX_PC.md](docs/frontend-bff/NEW_CONCEPT_UI_UX_PC.md) で扱う。

## 1. コンセプトと判断

### 1-1. コンセプト

> 多面性を整理し、自己理解を深めるための短文記録SNS

複数のフェイスに短文で思考を残し、後から見返すことで、自分の関心・感情・思考の流れを把握しやすくする。

### 1-2. 主役ユーザー

主役は **自分の思考を整理したい人** である。

- 断片的な思考や気づきをすぐ残したい
- 複数の関心事を混ぜずに管理したい
- 過去の自分を見返して傾向を知りたい

他人の記録を見る行為は、主目的ではなく **補助的な刺激収集** と位置付ける。

### 1-3. 毎日開く理由

MultiFace を毎日開く理由は、次の 3 つが並列で成立する状態を目指す。

- **書くため**
- **振り返るため**
- **刺激を集めるため**

`Writing` / `Reflection` / `Collect` は優先度の上下ではなく、自己理解を成立させるために相互補完する主機能として扱う。

### 1-4. 自己理解が起きたと判断する瞬間

ユーザーが次のいずれかを認識できた状態を「自己理解が起きた」と定義する。

- 自分が繰り返し書いているテーマに気づいた
- 以前より増えた／減った関心に気づいた
- 保存した刺激をきっかけに自分の考えを書けた

### 1-5. 非目的

- 他者との会話を増やすこと
- 人気や評価を競わせること
- 長文前提の知的生産ツールに寄せること

## 2. 既存機能との整理

既存の MultiFace には「自分で書く体験」と「他人の投稿を見る体験」が混在している。
新構想では、自己理解に直結しない要素は優先順位を下げる。

| 既存機能                       | 新構想での扱い                                     | 判断                      |
| ------------------------------ | -------------------------------------------------- | ------------------------- |
| フェイス                       | 多面性を整理する中核概念として維持                 | 継続                      |
| アクティビティ投稿             | 短文記録の主導線として再設計                       | 継続                      |
| サブスクライブ                 | 他者起点の導線のため新構想の中心から外す           | 本ドキュメントのMVP対象外 |
| 通知                           | 自己理解に直結しないため新構想の中心から外す       | 本ドキュメントのMVP対象外 |
| 検索                           | 自分の過去投稿・保存箱・静かな発見に限定して再設計 | 継続                      |
| リンク                         | 自分の思考の関連付けとして再設計余地がある         | 本ドキュメントでは未定義  |
| いいね / 返信 / フォロワー訴求 | 心理的ハードルを上げる                             | 不採用                    |

## 3. 便益

### 3-1. ユーザー便益

- カテゴリ別に投稿できるため、思考を整理しやすい
- 過去の自分の投稿を見返せるため、思考の軌跡を追いやすい
- 他人の評価を気にせず書けるため、着手しやすい

### 3-2. 競合差別化

- X/Twitter より気軽で、反応を気にしなくてよい
- Notion より軽く、入力開始までが早い
- SNS より静かで、メモアプリより思考を横断して見返しやすい
- 投稿する場ではなく、**自分の思考の流れを観察する場** である

## 4. 中核体験

### 4-1. コアループ

> 思いつく → すぐ書く → たまる → 見返す → 気づく → また書く

新機能は、このループを強める場合のみ採用する。

### 4-2. 3つのメイン機能

#### Writing

思考の種を最短で残す。

- 1タップで入力開始できる
- フェイス候補が提示される
- 公開 / 非公開を切り替えて保存できる
- 下書きより軽い「種」として一時保存できる

#### Reflection

蓄積した記録群に対する直接のアクセスと管理を行う一覧機能。

- 作成したフェイスの一覧・管理
- それぞれのフェイスへの素早い絞り込み
- 過去投稿との再会と、素早い読み返し

#### Collect

他人や外部から刺激を拾い、自分の思考へ変換する。

- 発見画面から刺激に出会える
- 保存時にメモを残す
- 保存物に関連フェイスを付ける
- 保存箱から投稿を作成する
- 発見は人気ではなく「思考の近さ」や「関心の近さ」を優先する

## 5. ドメイン定義

実装時に曖昧さが出ないよう、UI 上で扱う単位を定義する。

### 5-1. フェイス

- ユーザーごとに作成する思考カテゴリ
- 例: 仕事 / 日記 / 読書 / 体調 / アイデア
- 各フェイスには顔となる画像（関連するアイコンやイメージ画像）を設定できる
  - **重要**: フェイス名やカテゴリの内容が一目で分かるよう、人の顔ではなく、テーマに適した画像（例：本のアイコン、PCの写真など）を大きく目立つように表示する
- 公開範囲は `private` / `public` の2値とする
- 初期値は `public`

### 5-2. 投稿

- フェイスに紐づく短文記録
- 投稿状態は次の2種類
  - `published`: 通常投稿
  - `seed`: 一時保存された未整理の種
- 公開範囲は `private` / `public` の2値とする
- 初期値は `public`
- 文字数は **推奨 140 字以内、上限 5000 字**

### 5-3. 保存アイテム

- 他人の公開投稿、または外部 URL / テキストメモを保存したもの
- 保存時に必須入力する項目
  - 気になった理由（1行以上）
  - 関連フェイス（1つ以上）

### 5-4. 週次レビュー

本機能は要件変更によって分析機能と合わせて削除されたため、MVPでは扱わない。

## 6. UX上の重要原則

- 他人の評価を見せすぎない
- 長文作成より短文蓄積を気持ちよくする
- 見返し導線を投稿導線と同じくらい強くする
- 発見は“他人”より“過去の自分”を優先する

### やらないこと

- レコメンドを強くしすぎる
- 通知を増やしすぎる
- 人気・反応・ランキングを前に出す
- 交流導線を増やす
- 何でもできる知的生産ツールに寄せる

## 7. MVPスコープ

本ドキュメントで定義した `Writing` / `Reflection` / `Collect` の機能は、すべて MVP の実装対象とする。
段階的に一部のみを実装する前提は置かず、自己理解の体験が 3 タブで一通り成立することを MVP 完了条件とする。

### 7-1. MVPに含める機能

- Writing
  - クイック投稿
  - 一時保存（種）
  - フェイス候補提案
  - 自分の投稿一覧
  - 自分の投稿検索
- Reflection
  - 再発見・過去投稿との再会
  - フェイス横断ビュー
  - フェイス一覧・管理
- Collect
  - 種一覧
  - 保存アイテム一覧
  - 発見画面
  - URL / テキストメモ保存
  - 保存アイテムと投稿の関連付け
  - 保存箱から投稿作成
  - 他人投稿 / 外部情報からの刺激収集

### 7-2. MVP完了条件

- `Writing` / `Reflection` / `Collect` の 3 タブで主要導線が完成している
- ユーザーが「書く」「振り返る」「刺激を自分の記録へ変える」を一通り行える
- フェイス管理を含む自己理解の基本体験が、タブを横断して破綻なく成立している

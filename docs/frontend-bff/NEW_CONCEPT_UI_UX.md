## 2. 共通ナビゲーション方針

MVP の主要ナビゲーションは、3つのメイン機能と一致する次の 3 タブとする。

| タブ       | 役割                                                 |
| ---------- | ---------------------------------------------------- |
| Writing    | すぐ書く（投稿フォームがデフォルト）                 |
| Reflection | 週次レビューと再発見 / 投稿履歴 / フェイスを管理する |
| Collect    | 種・保存アイテムの整理                               |

### 共通ルール

- `Writing` / `Reflection` / `Collect` は、そのままタブ名称として使用する
- アプリ起動時の初期表示タブは常に `Writing` とする
- フェイス管理は独立タブではなく、`Reflection` 内の導線として持つ
- 検索は独立タブではなく、`Writing` と `Collect` の画面内導線として持つ
- 通知・サブスクライブは MVP の主要ナビゲーションに置かない
- `Writing` は 3 タブの中で最も「書く」体験を優先し、情報を詰め込みすぎない
- `Writing` のファーストビューでは、入力欄を最も大きく目立つ要素として配置する

## 3. デバイス別の責務分担

### 3-1. スマホ比率

- 片手操作での入力開始を最優先する
- 1画面1目的を基本とする
- CTA は親指で届く位置に配置する
- 投稿、保存、振り返りはシートや縦積みレイアウトを優先する
- 起動直後は `Writing` タブを開き、まず入力欄が目に入る構成にする

### 3-2. PC比率

- 一覧と詳細、一覧と入力を同時に扱いやすくする
- 横幅を活かし、比較・見返し・編集の往復を減らす
- キーボード操作と複数ペイン表示を前提にする
- 長時間利用でも情報の見通しが崩れない構成を優先する
- 起動直後は `Writing` タブを開き、最初の視線が入力欄へ向く構成にする

## 4. Reflectionカード仕様（推奨）

`Reflection` は分析・推論よりも「フェイスごとの一覧と管理」を主たる目的とする。

### 4-1. フェイス一覧カード

- 表示内容
  - フェイス画像（テーマに適したアイコンやイメージ画像を大きく目立つように表示）
  - フェイス名
  - そのフェイスに紐づく投稿数・種件数
- 推奨UI
  - 縦長の長方形（中に正方形の画像、下部にタイトルと詳細）の2列グリッドカード
- タップ時の挙動
  - 対象テーマの詳細 / 投稿閲覧画面へ遷移

### 4-2. 最近の記録タイムライン

- 表示内容
  - 直前の投稿内容、または保存した種
- 推奨UI
  - 短文ベースの縦積みカードリスト
  - 画像付きの場合は、テキストを主役として上部に配置し、画像は下部に配置する
  - 画像付きの場合は、テキストを主役として上部に配置し、画像は下部に配置する
  - 画像付きの場合は、テキストを主役として上部に配置し、画像は下部に配置する
- タップ時の挙動
  - 投稿の詳細を見るか、内容を編集する

### 4-3. 昔保存した種との再会

- 表示内容
  - 一定期間見返していない `seed` または保存アイテム
  - 現在の関心に近い理由
- 推奨UI
  - `今のあなたに近いかも` の補助文付きカード
- タップ時の挙動
  - `Collect` タブの該当詳細、または `Writing` への投稿変換導線を開く

### 4-9. フェイス横断ビュー

- 表示内容
  - 複数フェイスで共通して出現する語やテーマ
  - 関連するフェイス名
- 推奨UI
  - テーマ単位のカード + 紐づくフェイスタグ
- タップ時の挙動
  - 横断検索結果、または関連投稿一覧へ遷移

## 5. フェイス候補提案の表示ルール（推奨）

`Writing` の候補提案は、入力の邪魔をしないことを最優先にする。

### 5-1. 表示タイミング

- 本文が 20 文字以上入力された時点で初回判定する
- 以後は入力停止 600ms 後に再判定する
- 文字数が短い間は候補表示を出さない

### 5-2. 表示件数

- 候補は最大 3 件まで表示する
- 先頭 1 件を推奨候補とし、残りは代替候補とする

### 5-3. 表示位置

- 入力欄の直下にインライン表示する
- フェイス選択 UI と近い位置に置き、視線移動を最小にする

### 5-4. 表示内容

- フェイス名
- 推奨理由の短い補足
  - 例: `最近このフェイスでよく書いています`
  - 例: `本文中の「読書」「本」に近い内容です`

### 5-5. 候補ゼロ時

- 空の候補枠は表示しない
- 代わりに `フェイスを選択してください` のみ表示する

### 5-6. ユーザー操作との優先関係

- ユーザーが手動でフェイスを選んだ後は、自動提案で上書きしない
- 投稿途中で本文が変わっても、明示的に再提案を押さない限り選択中フェイスは保持する
- `seed` 保存時はフェイス未選択を許可する

---

## 6. 初回ユーザー導線（推奨）

初回ユーザーは、最短で `Writing` へ入りつつ、最低限のフェイス作成と初回投稿まで迷わない導線を持つ。

### 6-1. 初回起動フロー

1. アプリ起動
2. `Writing` タブを初期表示
3. フェイス 0 件を検知
4. `まずは 1 つフェイスを作りましょう` の案内を表示
5. `Reflection` タブ内のフェイス管理を開く
6. 最初のフェイスを 1 件作成
7. 自動で `Writing` タブへ戻る
8. 初回投稿入力を促す

### 6-2. 初回案内で伝えること

- フェイスは思考を分けるカテゴリであること
- 後から増やせるため、最初は 1 つでよいこと
- まずは短文 1 件書けば使い始められること

### 6-3. 初回完了条件

- フェイスを 1 件以上作成済み
- 投稿または `seed` を 1 件以上保存済み

### 6-4. 初回未完了時の再案内

- 次回起動でも `Writing` タブを初期表示にする
- 上部に小さな案内バナーを再表示する
- 強制的にモーダルを毎回出さない

---

## 7. 共通検索仕様

MVP の検索対象は、自己理解に関係する範囲へ絞る。

### 7-1. 検索対象

- 自分の投稿
- 自分の種
- 自分の保存アイテム

### 7-2. 検索条件

- キーワード部分一致
- フェイス絞り込み
- 期間絞り込み

### 7-3. MVPでやらないこと

- サービス全体の人気順表示
- 他人投稿の大量レコメンド
- ランキング型 UI

---

## 8. 共通の公開範囲・プライバシー方針

- 投稿とフェイスの公開範囲は `private` / `public` のみ
- UI 上の初期値は両方 `public`
- 週次レビューは **private / public を問わず自分の全記録を集計対象** とする
- 保存アイテムは常に自分専用で、MVP では公開しない
- 他人に見せる前提の導線は主導線に置かない

---

## 9. 共通の UI 数値ルール

「気軽さ」を担保するため、次を明文化する。

- 初回投稿完了までの操作は **最大 3 アクション**
- 投稿時の必須入力は **本文のみ**
- 公開変更は任意の追加操作とする
- 振り返り画面では、1 分以内に最低 1 つの気づきが得られる情報量を優先する

デバイス別の表示密度やレイアウト条件は個別ファイルで定義する。

## 10. ISSUE分解の基準

以下の単位で実装 ISSUE を切る。

### Epic 1: クイック投稿

- Writing タブのクイック入力 UI
- `published` 保存
- `seed` 保存
- 直近使用フェイス初期選択
- フェイス候補提案

### Epic 2: フェイス管理

- フェイス一覧
- フェイス作成 / 編集 / 公開設定
- Reflection タブ内導線
- 振り返り結果からのフェイス編集導線

### Epic 3: 自分の記録一覧・検索

- Writing タブの投稿一覧
- フェイス絞り込み
- キーワード検索

### Epic 4: 振り返り

- Reflection タブの週次レビュー UI
- フェイス横断ビュー
- 再発見カード
- Reflection カード詳細仕様
- Writing タブへの導線

### Epic 5: 保存箱

- Collect タブの種一覧
- Collect タブの保存アイテム一覧
- Collect タブの発見画面
- Collect タブから Writing タブへの投稿変換
- 保存アイテムと投稿の関連付け

### Epic 6: デバイス別UI実装

- スマホ比率レイアウト実装
- PC比率レイアウト実装
- デバイスごとの差異検証

### Epic 7: 初回ユーザー導線

- 初回フェイス作成案内
- 初回投稿促進導線
- 初回未完了時の再案内

## 12. デザインシステム（Color Scheme & UI Token）

MultiFaceのコンセプトである「自己との対話（Reflection）」「直感的な記録（Writing）」「知の収集（Collect）」を体現するため、ノイズが少なく沈静感のある「スレート（Slate）」ベースの無彩色と、思索を深める「インディゴ（Indigo）」をアクセントとしたカラースキームを定義する。

### 基本カラートークン（Design Tokens）

#### 1. Primary Colors（ブランド・アクション）

- **Primary (`#4F46E5` / Indigo-600)**: アプリへの注目と冷静な思考を促す青紫。CTAボタン（「保存する」など）、アクティブなタブ、選択中のフェイスチップなど、主要アクションや導線を示すセマンティックカラーとして使用する。
- **Primary-Light (`#EEF2FF` / Indigo-50)**: インディゴの要素と組み合わせる淡い背景色として利用。

#### 2. Background & Surface Colors（背景・階層）

- **Background (`#F8FAFC` / Slate-50)**: アプリ全体のベース背景色。完全な白ではなく、わずかに青みを持ったスレートグレイを敷くことで、長時間のタイピングや画面の睨み合いにおける眼精疲労（Eye Strain）を軽減する。
- **Surface (`#FFFFFF` / White)**: カード UI、ダイアログ、ボトムシートなど「浮き上がる」要素の背景。Backgroundの色とのコントラスト差によって、視覚的に要素のかたまり（Elevation）を分割する。
- **Border (`#E2E8F0` / Slate-200)**: 基本的な枠線だが、本UIでは境界線の多用を避け、余白によるスペーシングと背景色の差異で情報設計（Information Architecture）を行うことを推奨する。

#### 3. Typography Colors（テキスト・可読性）

- **Text-Primary (`#0F172A` / Slate-900)**: 見出し、ユーザーが入力する主要なテキスト。画面上の最も強い情報を持たせる。
- **Text-Secondary (`#64748B` / Slate-500)**: タイムスタンプや補助的な説明、プレースホルダー。あえて視覚的階層（Visual Hierarchy）を落とし、Primary Textの邪魔にならないようにする。
- **Text-Inverse (`#FFFFFF` / White)**: Primary要素など、濃い背景の上に乗せる文字。十分なコントラスト比（WCAG AA以上）を担保して可読性を保つ。

これらの色は、アプリ全体の雰囲気を「質素」から「静かで思索的（モダン）」なテイストへ引き上げると同時に、ユーザーの集中力を阻害しない認知負荷設計に適している。

# MultiFace 新構想 UI/UX仕様（PC比率）

## このドキュメントの目的

本ドキュメントは、MultiFace 新構想の PC比率 UI/UX を定義する。
横幅を活かして、書く・見返す・整理するを同時に行いやすい構成を示す。
現在、詳細なワイヤーフレームやデザイン設計はFigma上で管理されているため、本ドキュメントでは全体の方針や仕様定義のみを記載する。

共通方針は [docs/frontend-bff/NEW_CONCEPT_UI_UX.md](docs/frontend-bff/NEW_CONCEPT_UI_UX.md) を参照する。

---

## 1. PC比率の基本方針

- 横幅を使って一覧と詳細を同時表示しやすくする
- キーボード操作を前提に、入力の往復コストを減らす
- 比較、見返し、編集を 1 画面内で継続しやすくする
- スマホ比率より情報量を増やしても、視線移動が整理される構成にする
- UIデザインの正本はFigmaとし、色（Slate-100、Indigoのグラデーション等）やマージンはFigmaの設定に従う。

---

## 2. ナビゲーション構成

- 画面上部に 3 タブを表示する
  - `Writing`
  - `Reflection`
  - `Collect`
- アプリ起動時は `Writing` タブを初期表示とする
- タブの下に各画面のローカルツールバーを置く
- 一部機能はサイドパネルまたは右ペインで補助表示する
- 初回ユーザーでも最初に開くのは `Writing` タブとする

---

## 3. 画面詳細仕様

## 3-1. Writing タブ

### 目的

書くことと直近の記録確認を、同じ画面内で素早く往復できること。

### レイアウト

2 カラム構成を基本とする。

- 左カラム
  - メイン入力カード
  - フェイスフィルターチップ
  - 再発見カード
- 右カラム
  - 最近の投稿一覧

### 表示優先順位

- 起動直後に最初の視線が集まる位置へ `メイン入力カード` を配置する
- `Writing` タブでは入力欄を主役にし、補助要素は入力開始を妨げない順序で置く
- 再発見カードは入力欄の下に置き、書く前に情報が勝ちすぎないようにする

### メイン入力カード

- 常時表示
- `Writing` 画面で最も大きい情報ブロックとする
- 一見して「ここに書く」と分かる見た目にする
- 要素
  - 本文入力欄
  - フェイス選択
  - `保存`
  - `種として保存`
  - 公開範囲切り替え
- 初期状態
  - 直近使用フェイスを選択
  - 公開範囲は `public`

### 投稿一覧

- 新着順
- 一覧上で `編集` / `種に戻す` / `削除` を操作可能
- 投稿選択時は右側詳細ペイン、またはインライン展開で全文確認できる

### AC

- 入力欄と投稿一覧を同時に見ながら操作できる
- アプリ起動直後、最初に視認される主要要素が入力欄である
- フェイスフィルタ適用時に一覧が即座に更新される
- 書く導線のために別画面遷移を必須にしない

### 初回ユーザー導線

- フェイス 0 件の場合、左カラム上部に初回案内パネルを表示する
- 案内パネルから `Reflection` のフェイス管理をサイドパネルまたはモーダルで開く
- フェイス作成後は `Writing` に戻り、入力欄へ自動フォーカスする

## 3-2. Reflection タブ

### 目的

フェイスごとの記録の管理・一覧表示を行い、過去の投稿履歴の確認と再会をサポートすること。

### レイアウト

2 カラム構成を主とする。

- メインカラム
  - フェイス一覧
  - 各フェイスの投稿件数 / 種件数等
- 補助カラム / または下部
  - 再発見カード群 / 行動 CTA
- サイドパネル (モーダルとして開く場合あり)
  - 特定フェイスの管理機能

### カード配置の推奨順

1. **フェイスカード群**
   - 自分が作成したフェイスの情報を正方形の2列グリッドで表示。
   - 各フェイスにはテーマに適した、大きく視認性の高い画像を合わせて表示する。
2. **最近の投稿履歴**
   - 直近行われた投稿内容のタイムライン表示。
3. **再発見カード群 / 再会**

### フェイス管理

- 右サイドパネル、またはモーダルで開く
- 一覧、作成、編集、公開設定を PC幅で一続きに操作できる
- 振り返りカードから対象フェイスをクリックすると該当フェイスの編集状態を開く

### AC

- 比較したいカード同士をスクロールしすぎず見比べられる
- フェイス管理を開いても振り返り情報の文脈を失わない

## 3-3. Collect タブ

### 目的

保存した材料を俯瞰し、まとめて整理・投稿化しやすくすること。

### レイアウト

3 ペイン構成を基本とする。

- 左ペイン
  - `種` / `保存アイテム` / `発見` 切り替え
  - 追加 CTA
- 中央ペイン
  - 一覧
- 右ペイン
  - 選択中アイテムの詳細
  - `投稿にする` アクション

### 発見画面

- `発見` を選ぶと中央ペインにおすすめ一覧を表示する
- 一覧に表示する項目
  - タイトルまたは冒頭文
  - 出典種別
  - おすすめ理由
  - 関連フェイス
- 右ペインでは選択中アイテムの詳細と `保存してメモする` を表示する
- 並び順は人気順ではなく、次を優先する
  - 関連フェイスとの近さ
  - 最近保存した内容との近さ
  - 最近書いた内容との近さ

### 保存入力

- モーダル、または右ペイン内フォームで入力する
- 必須入力
  - URL または本文
  - 気になった理由
  - 関連フェイス

### 投稿変換

- `投稿にする` 実行時は、Writing 用入力 UI をモーダルまたは別ペインで開く
- 元の保存内容を参照しながら本文を編集できる

### AC

- 一覧と詳細を同時に見ながら整理できる
- `発見` から保存導線へ即座に進める
- 保存内容を見失わずに投稿変換できる

---

## 4. PC比率の表示密度ルール

- 主要情報は折り返しすぎず、比較可能な横並びを優先する
- Writing タブでは入力欄を最も広く、最も目立つブロックとして確保する
- Writing タブでは 1 画面目に最低 5 件の投稿要約が見える密度を目安にする
- Reflection タブでは 2 系統以上のカード群を同時視認できる幅を確保する
- Collect タブでは一覧と詳細の同時表示を基本とする

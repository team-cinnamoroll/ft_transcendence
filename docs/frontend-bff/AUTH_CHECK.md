# ログイン導線 手動確認手順

> サインアップ／ログイン／ログアウトのフロントエンド実装（Issue #231〜#237）を手動で確認する手順。  
> 自動テスト（Playwright等）はまだ導入されていないため、現時点ではこの手順で確認する。

## 前提

- Dev Container（`docker compose -f docker-compose.dev.yml up`）で frontend・backend・PostgreSQL・Redis がすべて起動していること
- ブラウザで `http://localhost:8080`（Nginx経由）にアクセスできること

## テスト用メールアドレスの使い方（重要）

サインアップは同じメールアドレスで重複登録できない。**新しいメールアドレスが必要なのは「サインアップ画面自体」を確認するときだけ**で、それ以外の確認は最初に作った1つのテストアカウントを使い回せば十分。

- サインアップの確認: 毎回少し違うメールアドレスを使う（例: `test+1@example.com`, `test+2@example.com`）
- ログイン・ログアウト・`AccountMenu`の確認: 一度作ったテストアカウントで繰り返しログインし直せばよい

## 確認手順

### 1. サインアップ

- [ ] `http://localhost:8080/ja/sign-up` を開く
- [ ] 名前・メールアドレス・パスワード（8文字以上）を入力して送信する
- [ ] 成功後、ホーム（`/ja`）へ遷移することを確認する
- [ ] 同じメールアドレスでもう一度サインアップし、「登録に失敗しました」等のエラーが表示されることを確認する（重複エラー）

### 2. ログイン中の状態を確認する

- [ ] ヘッダー（モバイル）またはサイドバー（PC）の`AccountMenu`を開き、「ログアウト」項目が表示されていることを確認する
- [ ] `http://localhost:8080/ja/auth-check` を開く
  - [ ] 「現在のログイン状態」に `isAuthenticated: true` と `userId` が表示されることを確認する
  - [ ] 「backendから取得した本物のユーザー情報」に、サインアップ時に入力した`email`・`name`が表示されることを確認する（`getCurrentUser()`のモック名「山田 太郎」ではないことを確認する）

### 3. ログアウト

- [ ] `AccountMenu`の「ログアウト」を押す
- [ ] `/ja/sign-in` へ遷移することを確認する
- [ ] `AccountMenu`を開き直し、「ログイン」項目に変わっていることを確認する
- [ ] `http://localhost:8080/ja/auth-check` を開き、`isAuthenticated: false` になっていることを確認する

### 4. 再ログイン

- [ ] `http://localhost:8080/ja/sign-in` から、手順1で作成したメールアドレス・パスワードでログインする
- [ ] ホームへ遷移し、`AccountMenu`が再び「ログアウト」表示に戻ることを確認する
- [ ] 存在しないメールアドレス・間違ったパスワードでログインを試み、エラーメッセージが表示されることを確認する

## 後片付け

サインアップの確認で作った不要なテストユーザーは、以下の手順で削除できる（画面上に削除ボタンはまだ存在しない。[アカウント削除の実装]は/users/meが未実装のため保留）。

1. `auth-check`ページに表示されている本物のユーザー情報から`id`を控える
2. ブラウザのDevTools → Application → Cookie から `mf_access_token` の値を控える
3. 以下を実行する（**Dev Container内のターミナル**から実行する場合。`localhost:8080`はホスト側ブラウザ専用のポート転送であり、Dev Container内からは`backend`コンテナへ直接アクセスする）

```bash
curl -i -X DELETE http://backend:8000/api/v1/users/<控えたid> \
  -H "Authorization: Bearer <控えたアクセストークン>"
```

4. レスポンスの1行目（ステータスコード）を確認する

   | 返ってきた内容 | 意味 |
   | --- | --- |
   | `HTTP/1.1 204 No Content` | 削除に成功した |
   | `HTTP/1.1 404 Not Found`（body: `{"message":"user not found"}`） | 対象のユーザーが存在しない（すでに削除済み、または`id`の控え間違い） |

   より確実に確認したい場合は、同じ`id`に対して`GET`を投げて`404`が返ることを確認する（削除前は`200`が返る）。

   ```bash
   curl -i http://backend:8000/api/v1/users/<控えたid> \
     -H "Authorization: Bearer <控えたアクセストークン>"
   ```

## 既知の制約

- `auth-check`ページは `NODE_ENV=production` では `notFound()` により404になる（開発環境では表示される）
- ページ保護（未ログイン時に保護ページへ遷移できてしまう）は今回のスコープ外（[AUTH.md](AUTH.md) 参照）。未ログインのままでも既存ページはすべて閲覧できる
- アカウント削除の導線は未実装（別Issueで対応予定）
